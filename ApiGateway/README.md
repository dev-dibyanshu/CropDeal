# CropDeal API Gateway

This is the API Gateway for the CropDeal microservices project, built with Ocelot.

## Overview

The API Gateway acts as a single entry point for clients to access all four microservices:
- IdentityService
- CropService
- OrderService
- PaymentService

## Architecture

```
Client (React/Postman/etc.)
         │
         ▼
   API Gateway (Ocelot)
   http://localhost:5000
         │
    ┌────┼────┬─────────────┐
    ▼    ▼    ▼             ▼
Identity Crop Order      Payment
Service  Service Service  Service
:5238    :5159   :5168    :5074
```

## Service Ports

The gateway routes to these backend services:

- **IdentityService**: http://localhost:5238
- **CropService**: http://localhost:5159
- **OrderService**: http://localhost:5168
- **PaymentService**: http://localhost:5074

## Gateway Routes

### Identity Service
- `/api/auth/*` → IdentityService
  - POST `/api/auth/register`
  - POST `/api/auth/login`

### Crop Service
- `/api/crop/*` → CropService
- `/api/crops/listings*` → CropService (higher priority)
  - GET `/api/crop`
  - GET `/api/crop/{id}`
  - POST `/api/crop`
  - PUT `/api/crop/{id}`
  - GET `/api/crops/listings`
  - GET `/api/crops/listings/{id}`
  - POST `/api/crops/listings`
  - PUT `/api/crops/listings/{id}`

### Order Service
- `/api/order/*` → OrderService
- `/api/invoice/*` → OrderService
- `/api/receipt/*` → OrderService
- `/api/review/*` → OrderService

### Payment Service
- `/api/payment/*` → PaymentService
  - POST `/api/payment`
  - GET `/api/payment/history`
  - GET `/api/payment/{id}`
  - PUT `/api/payment/{id}/refund`

## Running the Gateway

### Prerequisites
All four microservices must be running first:

```bash
# Terminal 1 - IdentityService
cd IdentityService
dotnet run

# Terminal 2 - CropService
cd CropService
dotnet run

# Terminal 3 - OrderService
cd OrderService
dotnet run

# Terminal 4 - PaymentService
cd PaymentService
dotnet run
```

### Start the Gateway

```bash
cd ApiGateway
dotnet run
```

The gateway will be available at: http://localhost:5000

## Testing

### Through Gateway
```bash
# Register a new user
curl -X POST http://localhost:5000/api/auth/register \
  -H "Content-Type: application/json" \
  -d '{
    "fullName": "Test User",
    "email": "test@example.com",
    "mobileNumber": "1234567890",
    "password": "password123",
    "role": 1
  }'

# Get all crops
curl http://localhost:5000/api/crop

curl http://localhost:5000/api/crops/listings
```

```bash
# Direct IdentityService access
curl -X POST http://localhost:5238/api/auth/register \
  -H "Content-Type: application/json" \
  -d '...'

# Direct CropService access
curl http://localhost:5159/api/crop
```

## JWT Authentication

JWT tokens generated by IdentityService are automatically passed through to downstream services via the `Authorization` header. The gateway does not perform authentication - it simply forwards the header to the backend services.

Example with JWT:
```bash
# 1. Login to get token
TOKEN=$(curl -X POST http://localhost:5000/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"user@example.com","password":"password123"}' \
  | jq -r '.token')

# 2. Use token in subsequent requests
curl http://localhost:5000/api/order/my-orders \
  -H "Authorization: Bearer $TOKEN"
```

## Configuration

The gateway configuration is in `ocelot.json`. Routes, hosts, and ports can be modified there.

Key configuration sections:
- `Routes`: Defines upstream and downstream paths
- `DownstreamHostAndPorts`: Backend service locations
- `UpstreamHttpMethod`: Allowed HTTP methods
- `GlobalConfiguration`: Gateway base URL

## Technology Stack

- **ASP.NET Core 8.0**
- **Ocelot 25.0.2** - API Gateway
- **Swagger** - API documentation

## Notes

- The gateway does NOT have its own database
- The gateway does NOT implement business logic
- The gateway simply routes requests to appropriate services
- All existing microservices continue to work independently
- No changes were made to existing service code
